# ModulAI — рабочий план

Android-приложение: каталог нейросетей + модульная среда локального запуска
(текст, RP, исследования, код, картинки, звук, видео). Всё работает на устройстве,
модели берутся с Hugging Face, по ссылке или из файловой системы.

Целевое устройство для отладки: Xiaomi 15 (Snapdragon 8 Elite, Adreno 830, Hexagon NPU).

## 1. Стек

| Слой | Решение |
|---|---|
| UI | Kotlin, Jetpack Compose, Material 3, языки интерфейса RU/EN |
| Нативная часть | C++ (NDK, CMake), мост через JNI |
| Хранение | Room (чаты, персонажи, реестр моделей), DataStore (настройки) |
| Сеть | OkHttp + Ktor client, загрузки через WorkManager (докачка, пауза) |
| Сборка | Gradle, GitHub Actions собирает APK на каждый пуш |
| Мин. Android | 10 (API 29), только arm64-v8a |

## 2. Архитектура

```
app/                 оболочка, навигация, 18+ подтверждение при первом входе
core/
  runtime/           единый интерфейс Engine + менеджер памяти и загрузки моделей
  models/            реестр моделей, загрузчик, HF-клиент, импорт файлов
  catalog/           наш каталог (JSON) + подбор под память устройства
  agent/             цикл агента, инструменты, скиллы, MCP-клиент, журнал «закрытой среды»
  device/            RAM/SoC/NPU-детект, температура, zram/swap-информация
engines/
  llm-llamacpp/      GGUF: CPU + GPU (OpenCL Adreno)
  llm-qnn/           Qualcomm Genie/QNN: NPU, только заранее сконвертированные модели
  image-sdcpp/       stable-diffusion.cpp: CPU/GPU
  image-qnn/         SD на NPU (QNN-сборки моделей)
  audio-sherpa/      sherpa-onnx: TTS (Piper, Kokoro и др.), STT (Whisper), клон голоса
  vision-ncnn/       ncnn + Vulkan: апскейл (Real-ESRGAN), интерполяция кадров (RIFE)
modules/             пользовательские «пространства»
  chat/  rp/  research/  code/  image/  audio/  video/  lab/
```

Ключевой принцип: **модуль не знает о движке**. Модуль просит у `runtime` возможность
(`text-generation`, `image-generation`, `tts`…), `runtime` подбирает движок и бэкенд
(NPU → GPU → CPU) под модель и настройки. Новый движок = новая реализация `Engine`,
без правок в модулях.

«Свой движок» — это слой `core/runtime` поверх llama.cpp и остальных: собственные
планировщик памяти, пресеты, авто-режим, кэш промпта/KV, сборки с флагами под
конкретные SoC. Писать инференс с нуля не планируется — это годы работы без выигрыша.

## 3. Настройки запуска

- **Пресеты качества**: низкое / среднее / высокое / свой.
- **Рядом с пресетом**: размер контекста, effort (low / medium / high / ultra / auto).
  Effort управляет бюджетом размышлений (reasoning-токены, число шагов агента).
- **Авто-режим**: следит за скоростью (ток/с), заполнением контекста и температурой;
  при просадке сжимает историю (суммаризация), уменьшает бюджет размышлений,
  меняет число потоков. Привязывается к выбранному пресету.
- **Память**: mlock (запрет выгрузки весов в swap/zram), mmap вкл/выкл, показ
  свободной RAM и расширенной памяти. Системный zram без root не управляется —
  только поведение собственных страниц приложения.
- **Бэкенд**: авто / NPU / GPU / CPU, число потоков, привязка к большим ядрам.
- Расширенные: сэмплеры, шаблон чата, батч, KV-кэш на диск.

## 4. Модели и каталог

- **Источники**: встроенный каталог, поиск по Hugging Face (API), вставка ссылки HF,
  импорт локального файла (GGUF, safetensors, ONNX, QNN-бинарники).
- **Наш каталог**: JSON в репозитории (`catalog/`), обновляется из GitHub без
  обновления приложения. Запись: модель, квантизация, размер, требуемая RAM, тип
  задачи, языки (RU/EN), флаг «без цензуры», наше описание RU/EN, рекомендуемые
  пресеты, поддерживаемые бэкенды.
- **Подбор под устройство**: по RAM и SoC показываем «подходит / впритык / не
  влезет» и рекомендуем оптимальную квантизацию.
- Категории: текст, RP, исследования, код, картинки, апскейл, TTS, клон голоса,
  STT, видео-обработка, эксперименты.

## 5. Агентный слой («закрытая среда»)

- Основная модель в чате вызывает инструменты: `web_search`, `fetch_page`,
  `research`, `generate_image`, `tts`, `code`, пользовательские скиллы, MCP-серверы.
- **Журнал среды**: скрыт по умолчанию, открывается в один тап. Показывает мысли
  модели, вызовы инструментов, поисковые запросы, открытые сайты и что с них взято.
- **Режим исследования**: отдельная модель (или та же, в отдельном контексте)
  составляет запросы → DuckDuckGo → десятки страниц → извлечение текста и дат
  обновления → поэтапная выжимка (map-reduce, чтобы влезать в контекст) → отчёт с
  источниками → отдаётся основной модели. Запускается вручную или самой моделью.
- **Смена моделей в памяти**: менеджер решает, держать ли две модели сразу или
  выгружать основную на время работы инструмента (по доступной RAM).
- **Скиллы**: папка с описанием + промптом + набором инструментов; ставятся из
  каталога, по ссылке или из файла. **MCP**: клиент для удалённых серверов (HTTP).

## 6. Модули

| Модуль | Содержание |
|---|---|
| Chat | Основной чат, все инструменты, вложения, ветки диалога |
| RP | Карточки персонажей (формат Character Card V2/V3, совместим с SillyTavern), импорт PNG/JSON, подключение открытых каталогов, лорбуки, персона пользователя, эмодзи-стиль; создание персонажа через режим исследования |
| Research | Самостоятельный экран исследований с отчётами и источниками |
| Code | Кодер-модель, проект с файлами в песочнице, диффы, предпросмотр HTML/JS |
| Image | txt2img, img2img, inpaint, LoRA, апскейл; основная модель сама пишет промпт |
| Audio | TTS, создание голоса, клон голоса по образцу, STT (голосовой ввод) |
| Video | Апскейл кадров целиком (без кропа), увеличение FPS; генерация — эксперимент |
| Lab | Обучение маленьких сетей (до нескольких млн параметров), 3D — эксперимент |

## 7. Этапы

Статус: реализованы этапы 0–5 и 7–10: текст (CPU, GPU через OpenCL — по выбору,
по умолчанию CPU), каталог и поиск по Hugging Face, фоновые загрузки, инструменты и
веб-поиск, исследования, журнал среды, история чатов, авто-режим, ролевой модуль,
картинки (stable-diffusion.cpp), звук (whisper.cpp, Supertonic, Chatterbox), код,
скиллы и MCP, видео (покадровый апскейл, удвоение FPS смешиванием кадров).
Не сделано: NPU (нужен Hexagon SDK), нейросетевая интерполяция кадров (RIFE/ncnn),
онлайн-каталоги персонажей, редактор лорбука, обучение сетей и 3D (этап 11).
На реальном устройстве проверены только запуск, импорт модели и загрузка в чат.

Каждый этап заканчивается рабочим APK, который можно поставить и проверить.

0. **Каркас** — проект, CI со сборкой APK, навигация, 18+ экран, интерфейс `Engine`,
   детект устройства.
1. **Текст** — llama.cpp (CPU+GPU), чат со стримингом, загрузка модели по ссылке HF
   и из файла, пресеты, контекст, effort, mlock/mmap.
2. **Каталог** — наш JSON-каталог, поиск по HF, подбор под RAM, менеджер загрузок.
3. **Агент** — инструменты, журнал среды, веб-поиск, режим исследования, авто-режим.
4. **RP** — карточки, импорт, каталоги персонажей, лорбуки, генерация персонажа.
5. **Картинки** — stable-diffusion.cpp, затем NPU-модели, апскейл, вызов из чата.
6. **NPU для текста** — QNN/Genie, каталог готовых NPU-сборок под Snapdragon.
7. **Звук** — TTS, клон голоса, STT.
8. **Код** — кодер-пространство, вызов из основного чата.
9. **Скиллы и MCP** — установка скиллов, MCP-клиент.
10. **Видео** — апскейл и интерполяция кадров.
11. **Lab** — обучение маленьких сетей, 3D, генерация видео (по возможности железа).

## 8. Ограничения, о которых надо знать заранее

- **NPU.** Через QNN Hexagon требует модель, заранее сконвертированную под
  конкретный чип. Но в llama.cpp появился собственный бэкенд `ggml-hexagon`,
  который запускает обычные GGUF на NPU. Для его сборки нужен Hexagon SDK
  (проприетарный, скачивается с сайта Qualcomm). На этапе 6 сначала пробуем его,
  QNN остаётся запасным путём.
- **Генерация видео и 3D на телефоне** — на грани возможного: минуты–десятки минут
  на результат низкого разрешения. Поэтому в конце и с пометкой «эксперимент».
  Апскейл и интерполяция видео реальны, но небыстрые (секунды на кадр).
- **Размер моделей**: при 12–16 ГБ RAM комфортно до ~8B параметров в Q4; две модели
  одновременно (основная + исследователь) — только маленькие, иначе поочерёдно.
- **Проверка на железе**: сборка и юнит-тесты идут в CI, но скорость, NPU и память
  проверяются только на реальном телефоне — нужна обратная связь после каждого этапа.
- **QNN SDK** — проприетарный (лицензия Qualcomm), его библиотеки нельзя просто
  положить в открытый репозиторий; подключение будет отдельным шагом сборки.
